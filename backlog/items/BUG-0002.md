## Summary

`VnumJsonConverter<TVnum>` overrides `Read` and `Write` only. System.Text.Json serializes dictionary keys through `JsonConverter<T>.WriteAsPropertyName` and `ReadAsPropertyName`, whose base implementations throw. With the factory registered:

```csharp
JsonSerializer.Serialize(new Dictionary<Status, int> { [Status.A] = 1 }, options);
```

throws:

```
NotSupportedException: The type 'Status' is not a supported dictionary key using converter of type
'Skywithin.VnumEnumeration.Serialization.VnumJsonConverter`1[Status]'. Custom converters can add support
for dictionary key serialization by overriding the 'ReadAsPropertyName' and 'WriteAsPropertyName' methods.
```

Deserializing `{"a":1}` into the same dictionary type fails the same way. Confirmed by probe on 2026-10-26.

## Expected behaviour

Keys serialize as the code and deserialize from the code, case-sensitively, exactly like values. An unknown key throws `JsonException` with the same "Valid codes" message `Read` uses.

## Location

- `src/VnumEnumeration/Serialization/VnumJsonConverter.cs`
- `tests/VnumEnumeration.Tests/VnumJsonConverterTests.cs`
- `README.md`: "JSON serialization"

## Decision points

- Numeric keys: `Read` accepts numbers for backward compatibility, but a property name is always a string. Recommended: codes only for keys; do not try to parse `"1"` as a value.
- `JsonSerializerOptions.DictionaryKeyPolicy` applies to string keys; decide whether to honour it. Recommended: no, the code is the contract.

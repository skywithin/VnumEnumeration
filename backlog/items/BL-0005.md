## Context

Enumeration classes are routinely ordered by their numeric value, and `enum` values compare natively. `Vnum` implements `IEquatable<Vnum>` but not `IComparable`, so `Vnum.GetAll<T>().OrderBy(v => v)`, `SortedSet<T>` and `Array.Sort` throw `InvalidOperationException` ("Failed to compare two elements") at runtime. `LongEnumVnumTests.Comparison_WithLongValues_ShouldWork` compares `.Value` by hand, which is what every consumer has to do today.

## Scope

- Implement `IComparable<Vnum>` and `IComparable` on `Vnum`: order by `Value`; `CompareTo(null)` returns positive, as the BCL does.
- Comparing instances of different runtime types: throw `ArgumentException`, consistent with `Equals` being scoped to the runtime type. Ordering by type name first is the alternative; decide.
- Do not add `<` and `>` operators; keep the surface small. Decide.
- README "Behavior": add an "Ordering" paragraph.

## Decision points

- Cross-type comparison: throw, or order by type name first.
- Comparison operators: omit (recommended) or add.

## Acceptance criteria

- [ ] `OrderBy(v => v)` sorts by `Value`; `CompareTo(null)` is positive; cross-type `CompareTo` behaves as decided and is tested

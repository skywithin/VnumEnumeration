## Context

Enumeration classes are routinely ordered by their numeric value, and `enum` values compare natively. `Vnum` implements `IEquatable<Vnum>` but not `IComparable`, so `Vnum.GetAll<T>().OrderBy(v => v)`, `SortedSet<T>` and `Array.Sort` throw `InvalidOperationException` ("Failed to compare two elements") at runtime. `LongEnumVnumTests.Comparison_WithLongValues_ShouldWork` compares `.Value` by hand, which is what every consumer has to do today.

## Scope

- Implement `IComparable<Vnum>` and `IComparable` on `Vnum`: order by `Value`; `CompareTo(null)` returns positive, as the BCL does.
- Comparing instances of different runtime types: throw `ArgumentException`, consistent with `Equals` being scoped to the runtime type. Ordering by type name first is the alternative; decide.
- Do not add `<` and `>` operators; keep the surface small. Decide.
- README "Behavior": add an "Ordering" paragraph.

## Decision points

- Cross-type comparison: throw, or order by type name first.
- Comparison operators: omit (recommended) or add.

## Resolution (2026-10-26)

`Vnum` now implements `IComparable<Vnum>` and `IComparable`. The public `CompareTo(Vnum?)` returns positive for `null` and 0 for the same instance. For two instances of the same runtime type it returns `Value.CompareTo`, which cannot overflow at `long.MaxValue`. For different runtime types it throws `ArgumentException` (param `other`): "Cannot compare X with Y: Vnums are only ordered within one type." The non-generic `CompareTo(object?)` is an explicit implementation, so the public surface gains one method. It forwards Vnums, returns positive for `null`, and throws `ArgumentException` (param `obj`) for anything else.

Decisions, as recommended in the item: cross-type comparison throws, consistent with `Equals` being scoped to the runtime type; no `<`, `>`, `<=` or `>=` operators. The build's analyzers did not require the operators.

Ordering agrees with equality. `CompareTo` returns 0 exactly when `Equals` is true, including for two instances with the same value and different codes; a test pins this.

Tests cover `OrderBy`, `SortedSet<T>` and `Array.Sort` through the framework's default comparer; less, greater and equal; equal-value-different-code; null; cross-type; and the non-generic path. All pass on both targets.

Docs: README "Ordering" subsection after "Equality" and an Errors table row; CLAUDE.md equality bullet. Not breaking; no version impact.

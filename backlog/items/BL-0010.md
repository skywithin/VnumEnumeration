## Context

Every build emits five `CS1723` warnings from `src/VnumEnumeration/Serialization/VnumJsonConverter.cs` (lines 13, 15, 16, 17 and 63 at filing): `<see cref="TVnum"/>` refers to a type parameter, which needs `<typeparamref name="TVnum"/>`. Because the library builds with `GenerateDocumentationFile`, the shipped XML documentation carries the broken references. The test project adds two `CS8602` warnings (`LongEnumVnumTests.cs` lines 142 and 156: dereference of a possibly null `Deserialize` result).

A warning-free build is also the precondition for turning on `TreatWarningsAsErrors` when BL-0003 adds the trimming analyzers.

## Scope

- Replace the five `cref` uses with `typeparamref`.
- In the two tests, assert `NotNull` before dereferencing.

## Acceptance criteria

- [ ] `dotnet build VnumEnumeration.slnx` emits zero warnings
- [ ] The full test suite passes

## Context

Every build emits five `CS1723` warnings from `src/VnumEnumeration/Serialization/VnumJsonConverter.cs` (lines 14, 16, 17, 18 and 62 after BL-0003; the overrides BUG-0002 added already use `typeparamref`): `<see cref="TVnum"/>` refers to a type parameter, which needs `<typeparamref name="TVnum"/>`. Because the library builds with `GenerateDocumentationFile`, the shipped XML documentation carries the broken references. The test project adds two `CS8602` warnings (`LongEnumVnumTests.cs` lines 142 and 156: dereference of a possibly null `Deserialize` result).

BL-0003 (done) made only the IL2xxx/IL3xxx codes errors via `WarningsAsErrors`; once this item makes the build warning-free, `TreatWarningsAsErrors` can replace that list.

## Scope

- Replace the five `cref` uses with `typeparamref`.
- In the two tests, assert `NotNull` before dereferencing.

## Acceptance criteria

- [x] `dotnet build VnumEnumeration.slnx` emits zero warnings (both net8.0 and net10.0, library and tests)
- [x] The full test suite passes (140/140 on each target)

## Resolution (2026-10-26)

The five `<see cref="TVnum"/>` doc references in `VnumJsonConverter.cs` are now `<typeparamref name="TVnum"/>`, so the shipped XML documentation no longer carries broken references. The two `LongEnumVnumTests` deserialization tests assert `NotNull` before dereferencing, which clears CS8602; a null result would now fail with a clear assertion instead of a `NullReferenceException`.

Follow-up taken in the same change, with the user's approval: the library csproj now sets `TreatWarningsAsErrors`, replacing the IL-only `WarningsAsErrors` list BL-0003 added. It covers the IL trimming/AOT warnings too. Verified by building with a temporary file containing an unused variable: the build failed with `error CS0168`; the file was then removed. The test project was deliberately left out, because its package references could start failing the build through NuGet audit warnings that are outside this repo's control. CLAUDE.md's Commands paragraph describes the new setting.

Trade-off accepted: a future SDK upgrade that introduces a new library warning will fail the build until it is fixed.

## Context

The Architecture section of `CLAUDE.md` still describes the design before commit b6a9a34 ("Refactor Vnum instance discovery and lookup for performance and robustness", PR #3). As of 2026-10-26 three statements are wrong:

- "Results are cached per type in a static `ConcurrentDictionary` that is never invalidated." The cache is now the nested static class `Cache<TVnum>` holding an immutable `Lookup<TVnum>` published with `Volatile.Write`; there is no `ConcurrentDictionary`.
- "All lookups (`FromValue`, `FromCode`, `FromEnum`) go through the private `Parse` helper ..." There is no `Parse` helper. `Lookup<TVnum>` holds three dictionaries (by value, by code ordinal, by code ignore-case) and the throwing methods call the `Try*` methods and throw via `NotFound`.
- "The `TryFrom*` variants wrap the throwing versions and catch only `ArgumentException`/`ArgumentNullException`/`InvalidOperationException`." It is the other way round now: the `Try*` methods do the dictionary lookup and never throw (`TryFromCode(null, ...)` returns false), and the throwing versions wrap them.

Not mentioned at all: aliased fields are deduplicated by reference; null public static fields are skipped; and a lookup made during the type's static initializer (detected by a `.cctor` frame on the stack, see BUG-0001's resolution) returns a partial table that is not cached.

A session that reads the stale notes acts on the wrong model.

## Scope

Rewrite the `Vnum.cs` bullets of the Architecture section so each statement is verifiable against the code; keep the sentence about the exact exception message format (still true). BUG-0001 and BL-0001 (both done 2026-10-26) changed the build logic: null fields are skipped, a `.cctor` frame on the stack marks a reentrant lookup, and duplicate values, codes, or codes differing only by case throw `InvalidOperationException` from the first lookup. Describe that, not the old `TryAdd` first-wins behaviour.

## Resolution (2026-10-26)

The three `Vnum.cs` sub-bullets were rewritten as five: discovery and table build (DeclaredOnly fields, alias deduplication, null fields skipped, three dictionaries, duplicates throw from the first lookup and are never cached), publication and the reentrancy exception (`Volatile.Write`, `.cctor` frame detection via `DiagnosticMethodInfo`), lookups (`Try*` never throw, `From*` wrap them and throw via `NotFound` with the unchanged message format), the trimming annotations, and equality. The Commands paragraph now also says the IL analyzer codes are build errors. The converter bullet had already been updated by BUG-0002 and the test-helper bullet is still accurate, so both were left alone.

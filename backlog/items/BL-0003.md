## Context

`dotnet build src/VnumEnumeration/VnumEnumeration.csproj -p:IsAotCompatible=true` (2026-10-26) reports two analyzer warnings:

- `IL2090` at `Vnum.cs` line 241 (the `GetFields` call in `Cache<TVnum>.Build`): `'this' argument does not satisfy 'DynamicallyAccessedMemberTypes.PublicFields' in call to 'System.Type.GetFields(BindingFlags)'. The generic parameter 'TVnum' of 'Vnum.Cache<TVnum>' does not have matching annotations.`
- `IL3050` at `VnumJsonConverter.cs` line 130 (the `MakeGenericType` call in `VnumJsonConverterFactory.CreateConverter`): `Using member 'System.Type.MakeGenericType(params Type[])' which has 'RequiresDynamicCodeAttribute' can break functionality when AOT compiling.`

Discovery reads public static fields by reflection. Without `DynamicallyAccessedMembers` annotations the trimmer is not told to keep those fields, and consumers who publish with `PublishTrimmed` or `PublishAot` get no warning from this library; behaviour under trimming is unverified. ASP.NET Core minimal APIs with native AOT are a mainstream .NET 10 scenario, and the converter factory is the registration path for exactly that.

## Scope

1. Annotate the `TVnum` type parameter of `Cache<TVnum>`, `Lookup<TVnum>` and `VnumJsonConverter<TVnum>` with `[DynamicallyAccessedMembers(DynamicallyAccessedMemberTypes.PublicFields)]`, and the same on `TVnum` of every public generic method that reaches the cache (`GetAll`, `FromValue`, `TryFromValue`, `FromEnum`, `TryFromEnum`, `FromCode`, `TryFromCode`) so the requirement propagates to callers.
2. `VnumJsonConverterFactory.CreateConverter`: `MakeGenericType` over a reference type uses shared generic code, so it works under AOT in practice. Either mark the factory `[RequiresDynamicCode]` with a message (honest but noisy for consumers) or suppress IL3050 with a justification. Decide and record the reason.
3. csproj: `<IsAotCompatible>true</IsAotCompatible>` (implies `IsTrimmable` and turns on the analyzers) and, to keep it that way, treat the `IL*` warnings as errors, or `TreatWarningsAsErrors` once the build is otherwise warning-free (BL-0010).
4. Verify with a sample console app published with `PublishAot=true` that does `GetAll`, `FromCode`, `FromEnum` and a JSON round-trip through the factory. Record the command in the Resolution; it does not need to run in CI.

## Acceptance criteria

## Resolution (2026-10-26)

Every public lookup method, `Cache<TVnum>` and `VnumJsonConverter<TVnum>` now carry `[DynamicallyAccessedMembers(DynamicallyAccessedMemberTypes.PublicFields)]` on `TVnum`, so the requirement reaches consumers' call sites and the trimmer keeps the fields discovery reads. The csproj sets `IsAotCompatible` and lists the IL2xxx/IL3xxx codes in `WarningsAsErrors`, so the analyzers run on every build and a regression fails it.

A third warning had appeared since filing: IL2026 on `StackFrame.GetMethod()` in the reentrancy check BUG-0001 added. It now uses `DiagnosticMethodInfo.Create` (trim-safe, .NET 9+) and compares `Name` and `DeclaringTypeName`; a `#if !NET9_0_OR_GREATER` fallback keeps `GetMethod` with a justified suppression so BL-0008's net8.0 target will compile.

Factory decision: `CreateConverter` suppresses IL3050 and IL2071 with written justifications (reference-type-only instantiation shares canonical code; a Vnum type that reaches the serializer is referenced by the application, and its static constructor keeps the fields) rather than marking the factory `RequiresDynamicCode`, which would warn at every consumer's registration line.

Verification. The library builds with zero IL warnings. A scratchpad console app referencing the project, using a source-generated `JsonSerializerContext` with the factory registered, was published with:

```
dotnet publish -c Release -r win-x64 --self-contained -p:PublishTrimmed=true -p:TrimMode=full
```

Zero IL warnings from any assembly; the trimmed app passed all 14 checks: `GetAll`, `FromCode` (both cases), `FromValue`, `FromEnum`, a `TryFromValue` miss, a reentrant lookup during static init, a null-field type (skipped and cached), a duplicate type throwing, and JSON write, read and numeric read including a Vnum-keyed dictionary. `-p:PublishAot=true` failed before compiling anything with "Platform linker not found" (no Visual Studio Desktop C++ workload here), so native code generation is unverified on this machine. The AOT-specific risk is confined to the two suppressed sites, both reference-type generic instantiations that NativeAOT documents as supported.

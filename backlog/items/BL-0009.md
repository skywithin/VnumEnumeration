## Context

`src/VnumEnumeration/VnumEnumeration.csproj` carries the package metadata but none of the usual publishing hygiene, and both workflows pack with plain `dotnet pack`:

- No SourceLink settings (`PublishRepositoryUrl`, `EmbedUntrackedSources`), so consumers cannot step into the library's source.
- No symbols package (`IncludeSymbols` with `SymbolPackageFormat=snupkg`), so nothing reaches the NuGet.org symbol server.
- No `ContinuousIntegrationBuild=true` in CI, so the build is not reproducible and NuGet Package Explorer flags it.
- No `RepositoryType` or `PackageReleaseNotes` (a link to GitHub releases is enough).

## Scope

- csproj: `PublishRepositoryUrl`, `EmbedUntrackedSources`, `IncludeSymbols`, `SymbolPackageFormat=snupkg`, `RepositoryType=git`, `PackageReleaseNotes`. Recent SDKs include SourceLink for GitHub by default; confirm that no explicit package reference is needed.
- Workflows: pass `-p:ContinuousIntegrationBuild=true` to the build and pack steps. `dotnet nuget push *.nupkg` also pushes a `.snupkg` found beside it; confirm on the next `rc-v*` release.

## Acceptance criteria

- [ ] NuGet Package Explorer (or an equivalent check) reports Source Link and Deterministic as passing for a locally packed package
- [ ] After the next `rc-v*` tag, the symbols package appears on NuGet.org for that version
- [ ] Both workflows updated
- [ ] `dotnet build VnumEnumeration.slnx` and the full test suite pass

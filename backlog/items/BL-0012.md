## Context

Every lookup names the type at the call site, `Vnum.FromCode<OrderStatus>("x")`, and `FromEnum` needs two type arguments, `Vnum.FromEnum<OrderStatus, StatusId>(StatusId.Pending)`, because C# does not infer type arguments partially. The alternative used by Ardalis.SmartEnum and similar libraries is a self-referencing generic base (`Vnum<TSelf>`, `Vnum<TSelf, TEnum>`) that gives `OrderStatus.FromCode("x")`, `OrderStatus.List` and `OrderStatus.FromEnum(StatusId.Pending)`, with the cache living in the derived type's statics. It is a rewrite of the public surface, so it is recorded here as a question, not a plan.

## Questions to answer

1. What do the README examples look like under the self-referencing shape, including the enum-backed case with `Id` (two type parameters on the base)?
2. Can the current static entry points stay as thin forwarders so the change is additive rather than breaking, and what does that cost in surface area and confusion?
3. Do `static abstract` members buy anything for consumers here (for example a generic `TVnum.FromCode` constraint)?
4. In the Mayflower platform repo (the main consumer), how many `Vnum.From*<T>` and `Vnum.GetAll<T>` call sites exist, and how many would simplify? A count by call shape is enough.
5. What does the JSON converter factory look like when the base type is generic (it currently tests `typeof(Vnum).IsAssignableFrom`)?

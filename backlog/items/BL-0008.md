## Context

The package targets `net10.0` only. On 2026-10-26 the source compiled unchanged for `net8.0` (`dotnet restore -p:TargetFramework=net8.0` then `dotnet build`): every API used (`Unsafe.As`, `ReferenceEqualityComparer`, `ArgumentNullException.ThrowIfNull`, `Volatile`, `System.Text.Json` converters) exists in .NET 8. Consumers on the .NET 8 LTS cannot install the package today for no technical reason.

## Scope

- `src/VnumEnumeration/VnumEnumeration.csproj`: `<TargetFrameworks>net8.0;net10.0</TargetFrameworks>` (net9.0 is STS; skip unless wanted).
- `tests/VnumEnumeration.Tests/VnumEnumeration.Tests.csproj`: multi-target too, so the suite runs on both.
- Workflows (`.github/workflows/build-and-publish.yml`, `pre-release-publish.yml`): `actions/setup-dotnet` currently installs `10.0.x` only. Building `net8.0` needs only the reference pack from NuGet, but running the tests on `net8.0` needs the 8.x runtime: add `8.0.x` to `dotnet-version`.
- README "Supported frameworks" and the `PackageReference` example; the CLAUDE.md "Project" line.
- `Cache<TVnum>.IsStaticInitializerRunning` in `Vnum.cs` already has a `#if NET9_0_OR_GREATER` branch (`DiagnosticMethodInfo`, added by BL-0003) and a `GetMethod` fallback for older targets; confirm the fallback compiles and that the reentrant-lookup test passes on net8.0.

## Acceptance criteria

- [ ] `dotnet pack` produces `lib/net8.0` and `lib/net10.0`
- [ ] The full suite passes on both target frameworks locally and in both workflows
- [ ] README and CLAUDE.md updated
- [ ] `dotnet build VnumEnumeration.slnx` and the full test suite pass

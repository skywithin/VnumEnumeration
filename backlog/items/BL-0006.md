## Context

`VnumJsonConverter<TVnum>.Read` (`src/VnumEnumeration/Serialization/VnumJsonConverter.cs`, line 31 at filing) maps `""` to `null`, and README "Reading notes" documents it. Two problems, both confirmed by probe on 2026-10-26:

1. With `JsonSerializerOptions.RespectNullableAnnotations = true` and a non-nullable property, `{"S":""}` fails with `The property or field 'S' on type 'Holder2' doesn't allow setting null values. Consider updating its nullability annotation.` The real cause, an empty code in the payload, is hidden.
2. The explicit `JsonTokenType.Null` branch in `Read` (line 22) and the null check in `Write` are dead: `HandleNull` is false, so System.Text.Json never calls the converter for a null token or a null value. The branches suggest a contract the converter does not have.

## Scope

- Treat `""` like any unknown code: throw `JsonException` with the "Valid codes" list.
- Remove the dead null branches (or override `HandleNull => true` deliberately and test it; removing is simpler).
- README "Reading notes": `null` deserializes to `null`; an empty string is an unknown code.
- If a consumer needs empty-as-null, it can become a constructor option on the factory later; do not keep it as the default.

`breaking: true`: documented behaviour changes.

## Acceptance criteria
